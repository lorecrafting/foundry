# Review 4 supplement: a narrower callback context

This records the coordinator's follow-up after the review notes were submitted. It does not amend the archived verdict notes or constitute another lane receipt.

A limited direct-callback rule is a better fit for the concrete PP need than a generic capture-identity relation engine: permit the local/remote normalization only when the capture is the direct mapper argument of compiler-resolved `Enum.map/2` or `Enum.flat_map/2`, its arity is one, and the existing unique caller/target relocation and body correspondence checks hold. Refuse returned captures, captures placed in tuples/maps/lists, indirect variables, arbitrary callbacks and other contexts by default. That would refuse both reviewed counterexamples. The compiler-expanded AST should establish exact module, function, argument position and immediate parent; merely finding an Enum call somewhere above the capture would admit returned or nested captures again.

I independently inspected the actual PP Reads source using `ast-grep --lang elixir -p 'Enum.map($$$ARGS)' --json`: the `public_receipt/1` and `public_reservation/1` captures at lines 1001, 1023 and 1024 are direct `Enum.map/2` mapper arguments. The coordinator additionally reports direct Enum contexts for the other changed PP captures. I have not implemented or run this callback restriction, nor independently enumerated every changed PP capture under it. The exact candidate and the separate pairwise experiment pass PP; those results do not establish that an unimplemented callback restriction passes.

Its defensible claim is preserved target invocation under these recognized consumers, with unchanged target bodies in a fixed code generation. It is not unrestricted capture-value or runtime equivalence. In particular, unknown custom Enumerable implementations, helper side effects, runtime code replacement, tracing/stack inspection and deliberate closure introspection prevent a universal theorem from the call name alone. A direct Enum context removes the concrete escaping-capture/equality failure under ordinary collection traversal, but the scope and exclusions must be explicit. Keep the consumer set limited to witnessed PP needs; do not infer that every Enum callback is interchangeable or build a general effect/escape analysis.
